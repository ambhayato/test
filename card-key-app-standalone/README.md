# カードキー管理アプリ(共有ファイル版・サーバー不要)

`index.html` 1ファイルだけで動く、サーバー不要版のカードキー管理アプリです。
社内の共有ネットワークドライブ上のJSONファイルにデータを保存することで、複数人・複数PCでデータを共有します。

## 必要環境

- **Google Chrome** または **Microsoft Edge**(ブラウザの「File System Access API」という機能を使用しています)
- Safari / Firefox では動作しません

## 使い方

### 1. 初回セットアップ(誰か1人が行う)

1. `index.html` を、全員がアクセスできる共有ネットワークドライブに置く(共有フォルダに置いてもよいですし、各自のPCにコピーして使ってもかまいません。データファイルさえ共有場所にあれば動作します)
2. ブラウザで `index.html` をダブルクリックして開く
3. 「共有データファイルに接続してください」画面で **「新規作成」** を押し、共有ネットワークドライブ内に `card-key-data.json` のようなファイル名で保存する

### 2. 2人目以降のセットアップ

1. 同じ `index.html` を開く(共有ドライブから直接開くか、各自のPCにコピーして開く)
2. 「既存のファイルを開く」を押し、1で作成した共有ドライブ上の `card-key-data.json` を選択する

一度接続すると、次回からは同じブラウザでファイルを開いた際に自動的に再接続を試みます
(ブラウザ側の権限確認画面が出た場合は「再接続する」を押してください)。

### 3. 通常の利用

左側のナビゲーションから「カードキー一覧」「利用者マスタ管理」「貸出登録」「利用履歴」を切り替えて使います。
画面右上の「更新」ボタンや、画面切り替え時に自動的に共有ファイルを再読み込みするので、
他の人が行った貸出・返却も反映されます(それでも最新にしたい場合は「更新」を押してください)。

## 制限事項

- **同時書き込みの競合**: 複数人がほぼ同時に貸出登録・返却操作をすると、後から保存した内容で上書きされる場合があります(排他制御はありません)。頻繁に同時操作が発生する運用には向きません。
- **対応ブラウザ**: Chrome / Edge のみ。Safari / Firefoxでは「このブラウザは非対応です」と表示されます。
- **リアルタイム反映ではない**: 他の人の変更は自動更新(20秒ごと)または画面切り替え時・「更新」ボタンで反映されます。今まさに誰かが操作した直後の状態が即座に見えるわけではありません。
- **接続の切れ直し**: OSやブラウザの再起動後など、ファイルへのアクセス許可が切れることがあります。その場合は「再接続する」ボタンで許可し直してください。

## Teams / SharePointへの公開

HTMLファイルをTeams/SharePointにそのままアップロードすると、多くの場合クリックしてもダウンロードされるだけで
アプリとしては開けません(SharePointがHTML内のスクリプト実行を防ぐための仕様のため)。
そのため、このアプリをどこかでWebサーバーとして配信し、そのURLをTeamsの「Webサイト」タブに登録する必要があります。
公開範囲に応じて2つの方法を用意しています。

### 方法A: 社内ネットワーク限定で公開する(推奨)

画面(アプリ自体)もインターネットには出さず、社内ネットワークの中だけで完結させる方法です。
追加の依存パッケージは不要で、Node.jsさえ入っていればすぐに使えます。

1. 社内の常時電源ONのPC/サーバーにこのフォルダ(`card-key-app-standalone/`)を配置する
2. そのPC上で以下を実行する
   ```sh
   cd card-key-app-standalone
   node serve.js
   ```
   `http://localhost:8080` で配信が始まります(ポートを変えたい場合は `PORT=9000 node serve.js` のように指定)
3. 社内の他のPCからは、そのPCの社内IPアドレスでアクセスできます(例: `http://192.168.x.x:8080`)。
   常時起動させ続けるには、ターミナルを開いたままにするか、Windowsのタスクスケジューラや `pm2` などでサービス化してください
4. 対象のチーム(チャネル)を開き、タブ一覧の「+」→「Webサイト」を選択し、3のURLを入力してタブ名(例:「カードキー管理」)を付けて保存する

社内ネットワーク(VPN含む)にいる人だけがアクセスできる状態になります。

### 方法B: インターネット上に公開してよい場合(GitHub Pages)

アプリの画面自体(データを含まない空のUI)がインターネットに公開されても構わない場合は、
**GitHub Pages** を使う方法もあります(`.github/workflows/deploy-pages.yml` で自動デプロイされます)。

1. GitHubのリポジトリ画面で **Settings → Pages** を開き、「Build and deployment」の **Source** を **GitHub Actions** に設定する(リポジトリ管理者が1回だけ行う)
2. `card-key-app-standalone/` 配下への変更をpushすると自動でデプロイされる(手動実行したい場合はGitHubの **Actions** タブから該当ワークフローを「Run workflow」)
3. デプロイ完了後、**Settings → Pages** 画面に表示される公開URL(例: `https://<ユーザー名>.github.io/<リポジトリ名>/`)を、方法Aと同様にTeamsの「Webサイト」タブに登録する

どちらの方法でも、データの共有・接続方法は上記の「使い方」の手順と同じです
(各自のブラウザで社内共有ドライブ上のデータファイルに接続します。データファイル自体は社内ネットワークの外からはアクセスできません)。

## Node.js版(card-key-app)との違い

このリポジトリには、常時起動するサーバーを使う `card-key-app`(Node.js版)もあります。
どちらを使うべきかの比較:

| | サーバー版 (card-key-app) | 共有ファイル版 (このフォルダ) |
| --- | --- | --- |
| 事前準備 | APIサーバーをどこかで常時起動しておく必要あり | 静的ファイルサーバー(`serve.js`)を常時起動するだけ、または共有ドライブに置くだけ |
| Teams連携 | 「Webサイト」タブでURLを登録できる | 同様に「Webサイト」タブに登録できる(方法A/B) |
| 対応ブラウザ | 制限なし | Chrome / Edgeのみ |
| 同時書き込み | サーバーが調停(競合しにくい) | 競合の可能性あり |
