IPアドレス制限（基幹システムからのみアクセス許可）

基幹システムのサーバーからのみアクセスを許可し、他のクライアントはすべて拒否する設定です。 IIS レベルでの制限と Azure レベルでの制限を組み合わせることで、多層防御を実現します。

推奨構成: Azure NSG（ネットワークセキュリティグループ）+ IIS IP 制限の両方を設定してください。 Azure NSG でネットワーク境界を守り、IIS で追加のアプリケーション層フィルタリングを行います。

方式の選択

環境推奨方式設定場所
Azure VM + IISAzure NSG + IIS IP 制限Azure ポータル + web.config
Azure App ServiceApp Service アクセス制限Azure ポータル（ネットワーク設定）

方式①: IIS IP 制限（web.config）

前提: 役割サービスのインストール

# IIS「IP とドメインの制限」機能をインストール
Install-WindowsFeature -Name Web-IP-Security

# インストール確認
Get-WindowsFeature Web-IP-Security

web.config の設定

サイトの web.config に以下を追加します。allowUnlisted="false" にすることで リストに登録されていない IP からのアクセスをすべて拒否します（ホワイトリスト方式）。

<system.webServer>
  <security>
    <ipSecurity allowUnlisted="false" enableReverseDns="false">

      <!-- IIS サーバー自身からのアクセス（ヘルスチェック等） -->
      <add ipAddress="127.0.0.1" allowed="true" />
      <add ipAddress="::1"       allowed="true" />

      <!-- 基幹システム: 単一 IP -->
      <add ipAddress="192.168.1.100" allowed="true" />

      <!-- 基幹システム: サブネット指定（複数台・クラスタ構成の場合） -->
      <!-- <add ipAddress="192.168.1.0" subnetMask="255.255.255.0" allowed="true" /> -->

    </ipSecurity>
  </security>
</system.webServer>

拒否された場合のレスポンス

デフォルトでは HTTP 403 (Forbidden) が返ります。 拒否時のレスポンスコードを 404 に変えることで、サイトの存在を隠すことができます。

<ipSecurity allowUnlisted="false" denyAction="NotFound">
  <!-- denyAction: Abort / Unauthorized / Forbidden / NotFound -->
  ...
</ipSecurity>

設定確認（PowerShell）

# 現在の IP 制限設定を確認
Get-WebConfigurationProperty `
    -PSPath "IIS:\Sites\MySite" `
    -Filter "system.webServer/security/ipSecurity" `
    -Name "."

# PowerShell で IP を追加する方法
Add-WebConfigurationProperty `
    -PSPath "IIS:\Sites\MySite" `
    -Filter "system.webServer/security/ipSecurity" `
    -Name "." `
    -Value @{ ipAddress="192.168.1.100"; allowed="true" }

方式②: Azure NSG（ネットワークセキュリティグループ）

Azure VM の場合、NSG でネットワークレベルの制限を設定します。 IIS に到達する前にトラフィックをフィルタリングするため、より堅牢です。

Azure CLI で NSG 受信規則を追加

# 既存の NSG に受信規則を追加
# （既存の全許可ルールより優先度を低い数値＝高い優先度で設定）

# 基幹システムからの HTTP/HTTPS を許可
az network nsg rule create \
  --resource-group myResourceGroup \
  --nsg-name myNSG \
  --name Allow-CoreSystem-HTTP \
  --protocol Tcp \
  --priority 100 \
  --source-address-prefix 192.168.1.100/32 \
  --source-port-range "*" \
  --destination-address-prefix "*" \
  --destination-port-ranges 80 443 \
  --access Allow

# その他すべてのインターネットからのアクセスを拒否
az network nsg rule create \
  --resource-group myResourceGroup \
  --nsg-name myNSG \
  --name Deny-All-Internet \
  --protocol Tcp \
  --priority 200 \
  --source-address-prefix Internet \
  --source-port-range "*" \
  --destination-address-prefix "*" \
  --destination-port-ranges 80 443 \
  --access Deny

方式③: Azure App Service アクセス制限

Azure App Service を使用している場合は、Azure ポータルまたは Azure CLI で アクセス制限を設定します（IIS の <ipSecurity> は App Service では機能しません）。

Azure CLI でアクセス制限を設定

# 基幹システムの IP からのみアクセスを許可
az webapp config access-restriction add \
  --resource-group myResourceGroup \
  --name myWebApp \
  --rule-name Allow-CoreSystem \
  --action Allow \
  --ip-address 192.168.1.100/32 \
  --priority 100

# 現在の設定を確認
az webapp config access-restriction show \
  --resource-group myResourceGroup \
  --name myWebApp

Azure ポータルでの設定手順

  1. Azure ポータルで App Service を開く
  2. [設定] → [ネットワーク] → [受信トラフィック] → [アクセス制限] をクリック
  3. [規則の追加] をクリック
  4. 名前・優先度・アクション（許可）・ソース（IP アドレス）・IP アドレス範囲を入力
  5. [規則の追加] で保存

設定後の動作確認

# 基幹システムのサーバーから疎通確認
# （基幹システムのサーバーで実行）
Invoke-WebRequest -Uri "https://your-manual-site.example.com" -UseBasicParsing

# 想定外のIPからアクセスされた場合: 403 または 404 が返る
# PowerShell での確認
try {
    Invoke-WebRequest -Uri "https://your-manual-site.example.com"
} catch {
    Write-Host "Status: $($_.Exception.Response.StatusCode)"
    # → 403 Forbidden または 404 Not Found
}

注意事項

  • 基幹システムが NAT やロードバランサーを経由している場合は、実際にリクエストを送信する出口 IP を許可する必要があります
  • Azure 内部通信（同一 VNet 内）の場合はプライベート IP アドレスを使用します
  • Azure Application Gateway を経由する場合は、Application Gateway の IP を許可します
  • 設定変更後はブラウザのキャッシュをクリアして動作確認してください
